# ode-classifier

Classify autonomous first-order differential equations

  **u′ = r(u)**, with r a rational function,

by **type** (exact, exponential or general) and as **new** or **old**. When an equation is old, the program returns an explicit substitution v = φ(u) and the simpler equation it comes from.

**Try it online, no installation needed:** https://sites.google.com/view/parthakumbhakar/software

## Background

Every first-order algebraic differential equation f(u, u′) = 0 belongs to one of four types: exact, exponential, Weierstrass or general. An equation is *old* if it comes from a "simpler" first-order equation through an algebraic substitution v = φ(u) of degree at least 2, and *new* otherwise.

Solutions of a new and general type equation cannot be expressed through classical functions, and any distinct nonconstant solutions are algebraically independent over ℂ.

For u′ = r(u) with r rational, Weierstrass type never occurs.

## Files

| File | What it is |
|---|---|
| `classify_ode.sage` | **Main program** (SageMath). Exact arithmetic over algebraic numbers and number fields. Uses the residue criterion and the divisor search described below. |
| `classify_ode.py` | **Lightweight fallback** (Python, SymPy + mpmath). No SageMath needed. Uses the divisor search only, with high-precision numerics for some checks. Slower on hard cases; use the Sage version for definitive results. |

## Usage

### SageMath (recommended)

From a terminal:

```
sage classify_ode.sage "u^2*(u-1)^3*(u-2)^5" "u/(u+1)"
```

Inside a Sage session or Jupyter notebook:

```
load("classify_ode.sage")
classify("(u^5 - u^3)/2")
r = classify("u*(u^2+1)^2/2")   # r['type'], r['new'], r['phi'], r['eta']
```

### Python

```
pip install sympy mpmath
python classify_ode.py "u^3 - u^2" "u/(u+1)"
```

Input: r(u) as a rational function in one variable with numeric coefficients; `I` and `sqrt(...)` are allowed. An input like `u' = u^3 - u^2` also works.

## Examples

| Equation | Result |
|---|---|
| u′ = u²(u−1)³(u−2)⁵ | general type, new |
| u′ = (u⁵ − u³)/2 | general type, old; φ = u⁻² |
| u′ = u³ − u², u′ = u/(u+1) | general type, new (Rosenlicht) |
| u′ = u(u²+1)²/2 | general type, old; v = 1/(u²+1) gives v′ = (v−1)/v |
| u′ = u⁹⁹⁹(u−1) | general type, new |
| u′ = u², u′ = 1 | exact type, new |
| u′ = u³ | exact type, old |
| u′ = u, u′ = u³ − u | exponential type, old |

## Method

Let ω = dx/r(x) be the associated 1-form on ℙ¹.

**Type.** Read off from the residues of ω: exact if all residues vanish; exponential if all poles are simple and all residues are rational multiples of one another; general otherwise. Exponential forms are always old; an exact form is new exactly when its only pole is a double pole.

**New or old (general type).** The Sage version combines two tests.

1. **Residue criterion.** Write ω = Σ aᵢ duᵢ/uᵢ + dv, where a₁, …, aₙ is a basis of the group generated by the residues (as in Noordman–van der Put–Top, §5.1). Then

   > ω is old ⟺ ℂ(u₁ᵈ, …, uₙᵈ, v) ≠ ℂ(x) for some 2 ≤ d ≤ B,

   where B = ⌊(deg of the zero divisor + number of zeros)/2⌋ bounds the degree of any pullback. Only the values of d allowed by the orders of the zeros and poles are tested. Each test computes the degree of the field extension as the size of a generic fibre.

2. **Divisor search.** If ω = φ\*η with deg φ ≥ 2, then after a Möbius change φ = ∏(x − P)^{e_P} / ∏(x − S)^{e_S}, with the P among the zeros and the S among the poles of ω, and exponents fixed by the orders and residues. This leaves finitely many candidates. A candidate works iff r·φ′ ∈ ℂ(φ), which is checked by exact linear algebra and gives η explicitly.

The program runs test 1 first. If it finds that ω is old, test 2 (restricted to the right degree) produces φ and η exactly. When the residues force enormous exponents in the uᵢ (for example u′ = u⁹⁹⁹(u−1)(u−2)), test 2 is used directly.

Neither test needs the Hurwitz realization problem, so newness is decided for **every** rational r.

## Limitations

- Coefficients must be numeric; symbolic parameters are not supported.
- Some steps use high-precision numerics to screen candidates; answers of the form "old" are always verified exactly.
- Large examples (many zeros and poles of high order) can take tens of seconds.
